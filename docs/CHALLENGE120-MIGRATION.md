# 2分間チャレンジ（120秒）・移行準備

## 今回の実装

共通ソース shared-src/site に10ゲーム共通の120秒モデル・画面・保存・採点連携を追加。確認用だけ有効。本番ファイル・Rules・Auth・データ・ランキング世代は変更しない。一般プレイヤー同期はオフを維持。

練習は時間無制限。既存の最高称号条件は20/47/47/26/25/25/25/20/25/25で不変。最高称号の旧達成記録からも解放し、開始ボタンを押すまで時計は動かさない。今回の挑戦は0連続から開始し、120秒中の最高連続だけを記録する。再挑戦で最高称号を取り直す必要はない。

保存先 mgl_challenge120_v1:{game} と mgl_challenge120_local_board_v1。protocol=2, mode=challenge120, season=preview-local-120-v1。開始時刻・終了予定時刻・進行・最高連続・自己ベストを保存。旧 mgl_best 等、称号・所持品・ウォレットを削除しない。ランキングの標準表示は2分間の端末内記録。旧記録は初回起動時に mgl_rankings_before_challenge120_v1 へ端末内バックアップを作り、旧ランキング表示にはその固定スナップショットを使用する。個人の過去最高は既存キーでも維持し、自動取り込みしない。

経過時間は保存した締切・Date.now・performance.now の最大値を利用。稼働中の時計巻き戻しで終了し、複数タブはWeb Locksで直列化。同一開始・同一回答ID・旧attemptの回答を拒否。期限後の回答をポイント保留キューへ追加しない。正解済みポイントは維持。通常1/50、2倍2/100、JST切替・同日の実績を維持する。

端末保存は端末時計・保存値自体を改変した相手への競技上の保証を持たない。特にブラウザを閉じて時計と保存値を同時に戻す改変は完全には検出できない。これは共有サーバー検証の完了とは別であり、公式共有ランキングは未接続と明示する。

## 共有保存と一括切り替え

challenge120-cloud-store.js と challenge120-season-store.js、Rules案 firebase/challenge120-proposed.rules を準備。Firebase Spark/Functions不要。サーバーrequest.timeを開始根拠にして120秒固定。開始時刻のserverTimestamp保存後、その時刻+120秒の締切を確定する二段階処理（中断・再送でも開始時刻は変えない）。期限後の回答・締切延長・早期再開始・他UID・protocol1・旧season書き込みをRulesで拒否。終了済みrunからのみ不変のresultとseason別entryを作れる。

採点自体はクライアント採点のため、改造されたクライアントが正誤を偽る攻撃までは防げない。questionIdは連続する再送を拒否するが、任意の新しいIDを発行する攻撃への正答証明にはならない。全ゲームのサーバー採点への変更は行っていない。

管理室の「全ランキングを新シーズンに切り替える」は、確認操作（全ゲーム・理由）、旧シーズンのバックアップ、監査記録、全10ゲーム共通ポインタの一括更新を1トランザクションで実施。バックアップ取得・保存の失敗時にはポインタは進まない。新seasonには旧記録をコピーしない。旧プログラムがplayersの旧bestを書いても新entryの掲載元にはならない。ランキング単独リセットの画面/APIは120秒版で停止する。

実環境は全10ゲームとも端末内記録で、seasonManagementEnabled:false のため一括切り替えは無効・共有未接続を表示する。切り替えたようには表示しない。Rules案は未公開。Firebase Console限定で準備する challengeVerification/ready の enabled/protocol/durationSeconds/games と全ゲームの保存検証が必要。児童にこの検証印を書かせない。

## 本番準備・差分

npm run build:both と node tools/prepare-challenge120.mjs で確認用・本番候補・検査記録を生成。本番候補は .release/production に隔離され全スクリプト安全停止。本番の公開フォルダへコピーしない。

firebase/production-challenge120-proposed.rules は既存の分配専用Rulesに追加する案。productionAdmin/v1 の専用権限・セッション・結果・シーズン領域だけを新設する。既存playersの許可項目は変更しない。新4ゲームなど本番の最高称号記録が端末だけにある場合、サーバーの解放条件を満たしたようには扱えない。共有保存前にUID・最高称号の移行方針と個別承認が必要。本番向け案はEmulatorで構文・代表的な権限制御を確認するが、実Firebaseへの反映は未承認。

## 切り替え順序（今回は実行しない）

1. 現行本番ファイルのコミット・ファイルハッシュ・Rulesを非公開バックアップ。児童データを移動・削除しない。
2. 専用テストUIDと実Firebaseで共有120秒保存を検証する承認を得る。10ゲームの最高称号・UID・共有接続を整備。一般同期は別途承認なしに有効化しない。
3. 必要最小限の本番Rules差分・認証・クライアントflagを個別承認後に適用。旧ランキング表示はそのまま。新seasonポインタはまだ切り替えない。
4. 120秒版を承認されたパッケージだけ公開し、10ゲームで動作を確認。問題があれば中止する。
5. 検証印とバックアップを確認し、管理室から全10ゲームの新seasonを原子的に切り替え。新entryはprotocol2・締切内回答から作った結果だけ。旧seasonと個人の過去最高記録は保持。
6. 新season書き込み・旧画面からの拒否を検証。

## 復旧

現行公開ファイルへコミット単位で戻す。今回追加した専用キーと旧記録は削除しない。共有切り替え前なら従来ランキングを引き続き表示。切り替え後の異常では、新entry受付を停止して記録を退避し、承認のもとバックアップの旧ポインタ・Rules・公開ファイルへ戻す。ポイント・称号・アイテム・児童文書を巻き戻さない。現在の確認用から戻す場合もpreviewだけの直前コミットへ戻し、Firebase Rulesは未変更なので変更不要。
