## 参照元と優先順位
**一次の基準は確認用サイト（preview/）とその実装設定・素材とする。** 新ゲーム、称号、報酬、ショップ仕様の現行案は確認用を正として管理し、本番 main に古い値が残っていても管理台帳の仕様を旧値へ戻さない。main は移行影響・既存利用者保護・未反映差分の照合対象。確認用コードと管理室の承認済み仕様が異なる場合は、自動的にどちらかへ上書きせず「要確認」として報告する。

- 移行比較用の本番設定: `profile-catalog.js`, `profile-model.js`, `profile.css`, `assets/avatars/avatar-concepts.png`, `assets/badges/*`
- **主要参照元・確認用設定:** `preview/profile-catalog.js`, `preview/profile-model.js`, `preview/economy-core.js`, `preview/profile.css`, `preview/assets/{avatars,frames,badges}/*`
- 確認用と本番は**別の状態**。確認用の存在を本番実装済みとみなさない。
- 承認履歴はこの管理室の会話に存在するが、画像の正式ID・原本との一致は別途検証する。

4. 確認用の枠にサイズ差・No.14/15加工欠損の懸念があり、素材の品質承認と実装承認は別。

6. 画像承認リストと `icon_NNN.png` / `frame_NN.png` の視覚的一致、ビット単位の同一性は別検証が必要。
7. **確認用を仕様管理上の基準とする**。本番との差分は移行時の影響・互換性・データ保護のため記録する。確認用と承認済み仕様の差異は承認なしに解決しない。

## 状態の定義
- `production`: 本番コードが参照
- `preview`: 確認用コードが参照
- `approved-design`: 管理室で見た目承認済み（品質・実装の保証ではない）
- `unverified`: 原本照合・実装品質未確認
- `legacy-protected`: 旧素材／既存ユーザー保護対象
- `deprecated-proposed`: 廃止候補（削除不可）
- `retired`: 移行と承認を完了した廃止済み

## 更新手順
1. 開発前にこのファイルと **preview/ 内の実装**の差分を確認。本番 main との比較は互換性・移行影響に限定。
2. 新素材には変更不能のID、原本パス、承認根拠、用途、状態を登録。名称だけで同一視しない。
3. 報酬の追加・変更は「ゲームID + 称号ID + 報酬ID」の三点を検証し、意図しないID重複を拒否。
4. 使用中素材の削除・ID変更前に、コード参照、購入履歴、所有者と装備情報を調査。
5. 確認用に変更後、検証結果とユーザー承認を記録。本番への反映は別の明示承認後。
6. 実装コード更新と同じ変更単位で台帳を更新する。差異があれば作業停止し報告。
