# 共通開発基盤（段階移行）

## 実装済み

- `shared-src/site/` は確認用サイトのHTML/CSS/JSの編集元。ゲーム、ランキング、プロフィール、ポイント、称号、管理室を一か所に集めた。
- `node tools/build-site.mjs preview` で `preview/` のプログラムを生成する。既存画像、端末保存、Firebaseデータを削除・移行しない。
- `node --test tools/foundation.test.mjs` で固定プロジェクト、別環境の設定混入、URLによる切り替え、未承認同期・管理認証の有効化を検査する。
- `node tools/check-site.mjs` で共通ソースと公開用生成ファイルのずれを検査する。
- 環境設定は公開Web設定のみ。パスワード、サービスアカウント、管理者トークンを記載しない。

## 未完了と公開制限

これは段階移行の最初の実装。本番の既存コードはまだ旧リリースのままであり、両環境の全面共通化が完了した状態ではない。

本番出力は意図的に停止する。本番は `/players/{uid}` の旧スキーマ、確認用は `previewSpark/v1/players/{uid}` のschemaVersion 2。現在の共通ソースには確認用限定の管理者検証と、旧本番向けのFirebase呼び出しが残る。生成時の環境検査だけでは、これら全処理の互換性やFirestoreのアクセス分離を保証しない。

本番Rulesはユーザー提供の現行全文を基準とする。現行Rulesには管理室用文書の許可もdistributionBestStreakもない。推測したRulesを公開しない。

本番ゲームは端末のnicknameをランキング保存で送信する。管理者による変更を正本とし、古い端末からの上書きを防ぐには、ゲームの保存アダプターとRulesの同時対応が必要。未対応のため本番への管理室移植は保留する。

確認用の一般同期はfalse。端末間の名前変更反映は未検証。現行のローカルランキング保存方式、最高記録、称号・報酬判定を変更しない。ランキング世代分離・3分間チャレンジ・ランキングリセットは導入しない。

## 標準手順

1. shared-src/siteを修正し、previewを生成する。
2. テストと生成差分検査を行う。確認用サイトで操作し、必要な場合だけ確認用FirebaseのRulesを検証する。
3. 本番のスキーマ・認証・Rulesとの差分、移行・バックアップ・復元手順をレビューする。
4. 本番機能と権限の承認後にのみ、別途用意する本番アダプターを検証し、停止ゲートを解除する。
5. 本番は別の出力ディレクトリへ生成してレビューする。生成処理から公開中のルートへ直接上書きしない。
6. 承認した変更だけ公開し、問題があれば直前コミットへ戻す。データ移行を行う場合は別途データ復旧手順を用意する。
